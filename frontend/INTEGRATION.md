# API 계약 반영 및 통합 대조 상태

사용자가 전달한 최신 계약과 `backend/app/schemas.py`를 기준으로 프론트엔드를 갱신했다. `backend/`, `docs/`, `CLAUDE.md`는 수정하지 않았다.

## 이번에 반영한 계약

### 생성·재생성 멱등키

- `POST /api/sessions`는 `{ request_id, presets }`를 전송한다.
- `POST /api/sessions/{id}/portrait/retry`는 `{ request_id }`를 전송한다.
- 요청 전에 ID와 선택값을 로컬에 저장한다. 응답을 확인하지 못한 재시도에는 같은 ID를 사용한다.
- 새로고침 후에도 미완료 요청을 복원해 같은 ID로 재시도한다.
- 생성 실패·거부가 응답으로 확정된 뒤 다시 그리는 동작은 새로운 요청이다. 새로운 ID를 사용한다.
- 성공한 재생성 뒤 사용자가 다시 그리기를 누르는 경우에도 새로운 ID를 사용한다.
- 목 전송 계층도 request_id를 필수로 검증하고, 응답 유실 시 저장된 결과를 재전달한다.

### 미확정 초상화 회차 복원

`GET /api/sessions/{id}`의 `portrait_confirmed`, `presets`를 사용한다.

- `portrait_confirmed=false`이면 `/appearance/{id}`의 초상화 확인 화면으로 이동한다.
- 외형 선택값, 초상화 상태와 URL, 잔여 재생성 횟수는 서버 응답으로 복원한다.
- 목록에서 미확정 회차를 선택하거나 다른 브라우저에서 직접 진입해도 대화 입력창을 열지 않는다.
- 이미 확정된 회차의 초상화 경로에 진입하면 대화 화면으로 이동한다.
- 새 외형 선택 화면은 계속 전부 미선택으로 시작한다. 기존 회차의 외형 복원과 구분한다.

### 과거 장면 이미지 복원

`GET /api/sessions/{id}`의 `scenes: [{ id, name, image_url }]`로 네 장면의 이름과 이미지를 복원한다.

- 목·실제 API 모두 같은 복원 함수를 사용한다. 목 서버 내부 이력을 직접 읽는 우회 경로는 제거했다.
- 로컬 턴 캐시가 없는 다른 브라우저에서도 완료 회차의 네 장면 그림을 읽을 수 있다.
- 서버가 image_url을 null로 반환하면 준비 중으로 표시한다. 오래된 로컬 이미지로 덮거나 URL을 만들어내지 않는다.

## 전달받아 확인한 사항

- **CORS**: 백엔드에서 해결했으며 로컬 개발의 `localhost:5173`을 기본 허용한다. 프론트에서 별도 변경하지 않았다.
- **오프닝**: 서버가 turn=0 메시지로 저장한다. 프론트는 GET 응답의 메시지를 그대로 렌더한다.
- **카드 원문**: `EndingResponse.card`의 별도 섹션에서 원문을 표시한다. 앞서 카드 원문과 player 메시지 ID 연결을 통합 이슈로 기록한 것은 오해였으며 철회한다. 이를 위한 API 변경이나 player 메시지 합성은 필요하지 않다.
- **관리자 도구**: `/admin`, `/api/admin/usage`는 게임 프론트의 구현 범위가 아니다.
- **카드 80자**: 프론트 grapheme과 서버 Python 코드 포인트 기준의 차이는 결정 보류 상태다. 이번 작업에서는 변경하거나 의존성을 추가하지 않았다.

## 남은 대조 사항

- **장면 진입 서술**: 3·6·9턴의 `scene.entered=true`일 때 마지막 narration을 진입 서술로 취급하는 기존 규칙을 유지한다. 기록 카드로 끝나더라도 구분선은 표시한다. 현재 반응과 진입 서술을 구분하는 최종 서버 메시지 순서는 실제 대화로 확인해야 한다.
- **장면 이미지 실패 구분**: scenes의 image_url은 준비 중과 생성 실패를 구분하지 않는다. 장면 재생성 경로도 현재 계약에 없다. URL 로드 실패에는 다시 불러오기를 제공한다.
- **실제 서비스 검증**: 응답 형태와 프론트 회귀 테스트로 검증했다. 실제 서버·DB·LLM·이미지 생성 서비스에 연결한 통합 실행은 별도로 필요하다.
