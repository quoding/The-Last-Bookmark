# 프론트엔드 비동기 장면·대화 흐름 개선 작업 기록

- 상태: 변경된 백엔드 실행 시점에 맞춘 프론트엔드 대응 완료

## 작업 기준과 범위

백엔드 API의 요청·응답 필드는 그대로 유지하고, 회차 생성 이후 장면 이미지가 백그라운드에서 준비되는 새 실행 시점에 맞춰 프론트엔드 동작을 수정했다. 구현과 문서 변경은 `frontend/` 안에서만 진행했으며 `backend/`, `docs/`, `CLAUDE.md`는 수정하지 않았다.

이번 기록은 날짜가 바뀌어 기존 기록에 이어 쓰지 않고 `worklog_codex/`에 새 파일로 작성했다. 파일명은 사용자가 지정한 `yymmhhmm_worklog` 형식에 Markdown 확장자를 붙였다.

## 구현 내용

### 장면 1 이미지 비동기 로딩

- `/start` 응답에서 첫 장면의 `image_url`이 `null`이어도 대화 화면을 즉시 연다.
- 대화 화면 진입 직전처럼 복원된 `turns` 배열이 아직 비어 있는 구간도 이미지 폴링 대상으로 포함했다.
- 0턴에서 장면 1 이미지가 준비되지 않은 경우 좌측 장면 영역에 스켈레톤을 표시하고 `GET /api/sessions/{id}`를 주기적으로 호출한다.
- 이미지가 준비되면 기존 복원 함수를 통해 현재·과거 장면 URL을 갱신한다.
- 목 서버도 회차 생성과 초상화 재생성 성공 시 장면 네 장의 생성이 시작되고 `/start`는 기다리지 않는 흐름으로 변경했다.
- 초상화 확정 전이라도 생성이 끝난 장면 정보는 서버 복원 응답에 반영되도록 목 동작을 맞췄다.

### 이미지 준비 문구

- 스켈레톤 표시 중 몇 초 간격으로 준비 문구가 순차 변경되도록 구현했다.
- 장면 이미지는 `가게로 가는 중...` → `책방의 불을 켜는 중...` → `책을 정리하는 중...` → `장면의 빛을 고르는 중...` 순서로 표시한다.
- 초상화도 표정과 조명, 마무리 과정을 나타내는 문구를 차례로 표시한다.
- 30초 이상 지연되면 기존의 장기 생성 안내로 전환하며 대화 입력은 계속 사용할 수 있다.

### 플레이어 메시지 즉시 표시

- 메시지 전송 직후 서버 응답을 기다리지 않고 플레이어 원문을 채팅 말풍선으로 먼저 표시한다.
- optimistic 메시지는 API 응답 타입이나 저장된 정식 턴을 변형하지 않고 별도 UI 상태로 관리한다.
- 서버 응답이 도착하면 임시 말풍선을 제거하고 응답에 포함된 player 원문과 reply·narration을 정식 턴으로 표시해 중복을 막는다.
- 응답 유실 후 새로고침한 경우 저장된 원문과 `request_id`로 optimistic 말풍선과 재시도 상태를 복원한다.
- 다른 회차로 이동한 뒤 이전 요청이 완료되어도 임시 메시지가 새 회차에 노출되지 않도록 회차 ID를 함께 관리한다.

### 타이핑 인디케이터와 스크롤

- 타이핑 인디케이터가 표시되는 시점에 대화 로그를 맨 아래로 이동해 점 세 개가 잘리지 않게 했다.
- 인디케이터에 `서윤이 답하고 있어요` 접근성 이름을 추가했다.
- 응답이 도착해 정식 턴으로 교체될 때도 하단 위치를 유지한다.

### 완료 회차 재열람 안내

- 완료된 회차의 대화 화면 상단에 `위로 스크롤하면 이전 장면을 볼 수 있어요.` 안내를 눈에 띄게 추가했다.
- 스크롤에 따라 당시 대화와 좌측 장면 그림이 함께 바뀐다는 설명을 덧붙였다.
- 완료 회차의 입력창과 종료 메뉴가 숨겨지는 기존 읽기 전용 동작은 유지했다.
