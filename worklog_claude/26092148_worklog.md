# 2026-09-07 작업 기록 (Claude) — 프론트 통합 대조 반영

## 배경
Codex의 프론트엔드 1차 구현 완료 보고(`worklog_codex/26092105_worklog.md`, `frontend/INTEGRATION.md`)를 검토하고,
실제 백엔드 코드와 대조해 확인한 문제를 고쳤다. 이어서 사용자가 요청한 계약 확장(코드별 저장 한도,
재진입 상태 노출, 코드별 API 키, 비용 모니터링)을 구현했다.

## 1. 즉시 수정 (버그, 계약 변경 아님)
- **CORS 미들웨어 부재**: 실제 브라우저에서 프론트↔백엔드 연결이 막혀 있었다. `CORS_ALLOWED_ORIGINS` 환경변수와
  `CORSMiddleware`를 추가했다.
- **오프닝 대사(turn=0) 미저장**: story.md 6.1의 첫 화면 설명·시작 대사가 어디에도 저장되지 않아 다른
  브라우저에서 재진입 시 복원이 불가능했다. `engine/opening.py`에 고정 텍스트로 옮기고 `/start` 호출 시
  turn=0 메시지로 한 번만 기록하게 했다.
- **테스트 하네스 버그**: `app.models`를 임포트하지 않은 채 단일 테스트 파일만 실행하면 `Base.metadata`에
  테이블이 등록되지 않아 `create_all`이 아무것도 만들지 않는 문제. `tests/conftest.py`에 `app.models` 임포트를
  명시했다.

## 2. Codex 대조 항목 중 "변경 불필요"로 확인된 것
- 카드 문장은 엔딩 근거 목록이 아니라 `EndingResponse.card`(별도 섹션, ui-spec 8.1의 3번 항목)에 원문 그대로
  들어간다. player 메시지 ID로 연결할 필요 없음.
- 장면 이미지 실패/재시도 경로 부재는 API 계약(CLAUDE.md 6장)에 의도된 설계다. ui-spec도 스켈레톤 표시로
  충분하다고 명시함.
- 장면 전환 시 "반응/진입 서술 구분"은 LLM 출력이 `reply`+`narration` 한 세트뿐이라(CLAUDE.md 8.1) 별도 필드가
  없다. 전환 턴에도 하나의 응답 안에 반응과 다음 장면 연결을 함께 쓰는 게 설계 의도(CLAUDE.md 7.2).

## 3. 사용자 요청으로 추가된 계약 확장
사용자와 직접 확인 후 진행:

- **회차 저장 한도를 코드별로 변경**: `IMAGE_BUDGET_SESSIONS`가 전체 코드 합산으로 세고 있던 버그를 고쳐
  코드 1개당 한도로 바꿨다. 기본값도 100 → 3으로 낮춤 (코드당 3가지 커스터마이징으로 3가지 엔딩을 보고
  싶다는 요청).
- **재진입 상태 복원 확장**: `GET /api/sessions/{id}`에 다음을 추가.
  - `portrait_confirmed`(bool), `presets`: 초상화만 만들고 "이 모습으로 시작하기" 전에 이탈한 회차인지
    구분해 프론트가 올바른 화면(초상화 확인/대화)으로 보낼 수 있게 함.
  - `scenes`: 4장면 이미지 전체 배열. 완료 회차를 다른 브라우저에서 열어도 장면 4장을 전부 복원 가능.
- **`POST /sessions`, `POST /portrait/retry`에 `request_id` 멱등 처리 추가**: 응답 유실 시 재시도해도
  중복 생성되지 않는다. (계약 변경 — 두 엔드포인트 모두 body에 `request_id`가 이제 필수)
- **코드별 API 키 분리**: `CODE_API_KEYS` 환경변수("code_id:api_key,code_id:api_key")로 초대 코드마다 다른
  LLM/이미지 API 키를 쓸 수 있게 함. muya98(개발/테스트용)과 tainai(제공용) 비용을 분리 추적하려는 목적.
  매핑에 없는 코드는 기존 전역 `LLM_API_KEY`/`IMAGE_API_KEY`로 폴백. `app/api/deps.py`, `app/api/deps_llm.py`에서
  코드별로 클라이언트 인스턴스를 캐시하고, 백그라운드 이미지 작업(`_run_background_scene_jobs`,
  `_run_ending_image_job`)도 세션의 code_id를 조회해 올바른 키를 쓰도록 수정.
- **API 비용 모니터링 페이지**: `api_usage_logs` 테이블에 LLM·이미지 호출마다 실제 토큰 사용량(text/image/output
  tokens)을 코드별로 기록. `/admin`(HTML 페이지) + `/api/admin/usage`(집계 API)를 `ADMIN_PASSWORD` 환경변수로
  보호해 추가. 비용(₩/$) 계산은 서버에 저장하지 않고 페이지에서 조회 시점에 단가를 입력해 계산한다
  (LLM_MODEL인 gpt-5.6-luna의 실제 단가가 아직 불확실하고, 이미지는 `docs/index.html`의 gpt-image-2 공식
  단가를 기본값으로 재사용). 이 두 라우트는 CLAUDE.md 6장 API 계약(프론트 접점)에는 포함되지 않는
  별도 관리자 도구다.

## 프론트(Codex)에 전달해야 할 계약 변경
1. `POST /api/sessions`, `POST /api/sessions/{id}/portrait/retry` 요청 본문에 `request_id`(string) 필수 추가.
2. `GET /api/sessions/{id}` 응답에 `portrait_confirmed`(bool), `presets`(PresetSelection), `scenes`(4개짜리
   `{id, name, image_url}` 배열) 필드 추가. 재진입 라우팅과 완료 회차 과거 장면 이미지 복원에 사용.
3. `/admin`, `/api/admin/usage`는 게임 화면과 무관한 별도 관리자 도구이므로 프론트 구현 대상이 아님.

## 남은 검증 항목

- 카드 80자 기준(그래프클러스터 vs 코드포인트) 불일치는 그대로 둠 — 새 의존성 없이 정확히 맞추기 어려워
  사용자에게 별도 보고, 아직 결정 없음.
