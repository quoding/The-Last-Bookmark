## 구현 내용

### 기반과 목 데이터

- Vite + React 18 + TypeScript + CSS Modules 구성.
- 상태 관리 라이브러리와 UI 프레임워크 없이 React 상태와 훅 사용.
- `src/types/api.ts`에 CLAUDE.md 6.1의 주요 응답 타입 정의.
- `src/types/server.ts`에 기존 백엔드 스키마의 보조 요청·응답 타입 반영.
- 12턴 대화, 장면 구분선 4개, 시스템 기록 카드 3종 구성.
- 엔딩 본문, 카드 문장, 플레이어 메시지 ID와 연결된 근거 대화 3개 구성.
- 완료 회차 2개와 7턴까지 진행한 회차 1개 구성.
- 외부 이미지 요청 없이 로컬 SVG 플레이스홀더 사용.
- 내부 관계 수치를 화면과 목 데이터에 넣지 않음.

### 시작과 외형 선택

- 초대 코드 입력, 이어서 하기, 새 이야기 시작, 회차 목록 구현.
- 목 환경은 임의의 4자 이상 코드로 접근하며, 실제 초대 코드 정답을 번들에 넣지 않음.
- 코드별 목 회차 분리 저장과 인증 시도 제한 구현.
- 외형 프리셋 7개를 2열 드롭다운으로 구성하고 한글 라벨을 그대로 사용.
- 초기값 전부 미선택, 전체 선택 시 생성 버튼 활성화.
- 주사위는 7개 축을 모두 무작위로 선택.
- 생성 전 텍스트 요약만 표시하고, 생성 후 초상화와 재생성 잔여 횟수 표시.
- 재생성 최대 2회, 생성 실패 재시도와 외형 재선택 처리.

### 대화와 카드

- 최대 1440px 중앙 정렬, 이미지 컬럼 480px, 1200px 미만 400px, 900px 미만 세로 스택 구현.
- 장면 이미지 크로스페이드, 과거 로그 스크롤에 따른 이미지 변경 구현.
- 로그 맨 아래로 돌아오면 현재 장면 이미지로 복귀.
- 시각, 장소, 얇은 시간 진행 막대, 완료 턴 수, 메뉴 구현.
- 서윤·플레이어·상황 묘사와 시스템 기록 카드의 표현 구분.
- 3·6·9턴 전환과 장면 구분선 처리.
- 행동 힌트, 여러 줄 입력, Enter 전송, Shift+Enter 줄바꿈, 한글 조합 중 Enter 구분.
- 응답 대기 표시와 일반 대화·카드 제출의 중복 실행 방지.
- 과거 대화를 읽는 동안 스크롤을 유지하고 새 대화 버튼 표시.
- 장면 3에서만 카드 편집기 제공. 공백·줄바꿈·이모지 원문 보존.
- 카드 80자 제한은 Intl.Segmenter의 사용자에게 보이는 문자 단위로 처리.
- 카드 확정·빈 채로 두기만 턴을 소비하며 편집기 열기·닫기는 소비하지 않음.
- 저장하고 나가기, 조기 종료 확인 모달, 마지막 입력 안내 구현.

### 엔딩과 회차 다시 보기

- 대화 화면과 다른 배경 톤과 여백으로 엔딩 화면 구성.
- 제목 → 본문 → 카드 문장 → 근거 대화 → 미해결 사항 → 하단 동작 순서 구현.
- 근거 카드는 다음 한 장씩 스크롤에 맞춰 공개.
- 각 근거에 시각·장면명·플레이어 원문·결말에 미친 영향 표시.
- 근거 클릭 시 해당 메시지 ID로 이동하고 원문을 강조.
- 긴 인용과 엔딩 재진입에서도 순차 공개가 이어지도록 보강.
- 완료 회차의 입력과 종료 메뉴를 숨기고, 대화와 그림을 다시 볼 수 있게 구현.
- 조기 종료는 마지막 완료 시각을 유지하고 발생하지 않은 문 잠금·작별을 추가하지 않음.

### API 계층과 실패 복원

- `src/api/client.ts`에 fetch 래퍼와 API 메서드 구성.
- `VITE_API_BASE_URL=mock://local`은 목 전송 계층, HTTP(S) 원점은 fetch 사용.
- Bearer 토큰 전송과 상대 이미지 URL의 API 원점 해석 구현.
- 제출 전에 request_id와 원문을 저장하고 실패 시 같은 요청으로 재시도.
- 응답 유실과 새로고침 뒤 완료 턴을 확인해 중복 소비 방지.
- 초상화·장면·엔딩 이미지의 준비 중 상태, 로드 실패, 재시도 처리.
- 30초 이미지 지연 시 안내 문구 전환.
- 엔딩 본문과 이미지 상태를 분리하고, 이미지 실패 중에도 본문 보존.
- 오프라인 안내와 화면 오류 복구 경계 구현.
- 개발용 실패 주입 기능은 일반 화면에 노출하지 않음.

## 남은 통합 대조 사항

상세 내용은 `frontend/INTEGRATION.md`에 기록했다.

1. 회차 복원 응답에 과거 장면 이미지 정보가 없어 다른 브라우저에서 그림 전체를 복원하는 계약이 필요함.
2. 서버 narration이 현재 반응인지 다음 장면 진입인지 구분하는 규칙을 맞춰야 함.
3. 시작 대화가 0턴 메시지로 저장·복원되는지 확인해야 함.
4. 초상화 미확정 회차의 목록 노출과 다른 브라우저에서 외형 복원 방식을 맞춰야 함.
5. 장면 이미지의 실패·거부 상태와 재생성 경로가 현재 계약에 없음.
6. 프론트의 grapheme 80자와 서버 Python len(text)의 코드 포인트 기준이 다름.
7. 서버 카드 경로는 Card에 원문을 저장하지만 player 메시지를 만들지 않아, 카드 원문을 엔딩 근거 ID로 연결하는 방식이 목과 다름.
8. 회차 생성·초상화 재생성의 응답 유실 시 중복 생성 방지를 대조해야 함.
9. 실제 API 인증·CORS·비동기 이미지 작업을 최종 연결해 검증해야 함.

## 추가 기록 — 2026-09-07 22:32 (Asia/Seoul)

### 전달받은 API 계약 변경 반영

- `POST /api/sessions` 요청에 필수 `request_id`를 추가했다.
- `POST /api/sessions/{id}/portrait/retry` 요청에도 필수 `request_id`를 추가했다.
- 요청 전에 ID와 선택값을 저장하고, 응답 유실·새로고침 후 같은 ID로 재시도하도록 구현했다. 응답으로 실패가 확정된 뒤 다시 생성하거나 사용자가 새로 그리기를 요청하는 경우에는 새 ID를 사용한다.
- 목 서버도 멱등키를 검증하고 저장된 응답을 재전달하도록 갱신했다. 생성·재생성 완료 후 응답만 유실되는 실패 주입을 추가했다.
- 회차 복원 응답의 `portrait_confirmed`, `presets`를 타입과 화면 라우팅에 반영했다. 미확정 회차는 초상화 확인 화면에서 서버의 선택값·이미지·잔여 횟수를 복원하고, 이미 확정된 회차는 대화 화면으로 이동한다.
- 회차 복원 응답의 `scenes: [{ id, name, image_url }]`를 사용해 장면 그림 4장을 복원한다. 로컬 캐시가 없는 다른 브라우저에서도 같은 경로로 복원할 수 있다.
- 목 서버 내부 이력을 직접 읽던 화면 복원 경로를 제거했다. 목·실제 API 모두 GET 응답을 사용하는 동일한 복원 함수를 거친다.

### 참고 사항 정정 및 범위 유지

- 이전 기록의 카드 원문과 player 메시지 ID 연결을 통합 이슈로 본 것은 오해였다. 카드 원문은 `EndingResponse.card`의 별도 섹션에 그대로 표시되므로 해당 연결을 위한 추가 계약은 필요하지 않다. `frontend/INTEGRATION.md`에서도 이를 정정했다.
- CORS와 turn=0 오프닝 저장은 백엔드에서 해결된 사항으로 확인했으며 관련 프론트 변경은 하지 않았다.
- `/admin`, `/api/admin/usage`는 별도 관리자 도구이므로 게임 화면에 추가하지 않았다.
- 카드 80자의 grapheme·코드 포인트 기준 차이는 결정 보류로 유지했다. 기준 변경이나 의존성 추가는 하지 않았다.
- 이번 구현에서도 `frontend/`만 수정했다. `backend/`, `docs/`, `CLAUDE.md`는 수정하지 않았다.
