# 2026-09-08 작업 기록 (Claude)

## 배경
사용자가 실제 플레이 후 피드백 6가지를 제시. 백엔드/프롬프트 이슈는 직접 처리하고,
순수 프론트 UX 이슈는 Codex에게 전달.

## 사용자 피드백 6가지 분류
1. 첫 장면 진입 대기시간이 김 → 백엔드 이슈로 확인, 아래에서 해결
2. 이미지 로딩 중 순차 안내 문구 필요 → 프론트, Codex 전달
3. 내 채팅이 상대 답장과 함께 늦게 뜸(카톡처럼 안 됨) → 프론트(optimistic UI 부재), Codex 전달
4. 응답 대기 인디케이터 뜰 때 스크롤 안 내려가서 잘림 → 프론트 버그, Codex 전달
5. 서윤이 종결형으로만 답해 플레이어가 다음에 뭐라 할지 막막함 → LLM 프롬프트 이슈, 직접 수정
6. 완료 회차 재열람 시 "위로 스크롤하면 이전 장면 보임" 안내 부재 → 프론트, Codex 전달

## 5번 — LLM 프롬프트 보강
`app/llm/prompts.py`에 `GUIDANCE_NOTES` 추가. "모든 답변을 질문으로 끝내지 않는다"는
기존 규칙만 있고 "가끔은 유도하라"는 지침이 없어 캐릭터가 너무 종결형으로만 답했다.
- 12턴 고정 구조라 플레이어가 막막해질 수 있다는 점 명시
- 자주(매번은 아니게) 다음 반응·선택 여지를 남기도록
- 장면 시작 직후에는 특히 여지를 주도록
- 고정 사건(책 추천, 카드, 문 잠그기)에 서윤이 먼저 다가가도 된다고 명시
실제 API로 재검증: 애매한 입력("그렇군요")에도 서윤이 구체적인 다음 행동을 제안하는 것 확인.

## 1번 — 장면1 이미지를 초상화 나오자마자 미리 생성
사용자가 정확히 이 방식을 제안: "커스터마이징한 캐릭 나오자마자 그거 참조해서 이미지
생성하고, 준비 안 됐으면 로딩 문구, 준비돼 있으면 바로 들어가지게".

- `POST /sessions`, `POST /portrait/retry` 성공 시 장면 1~4 전체를 `background_tasks`로
  즉시 시작 (이전엔 `/start`를 눌러야 장면1만 동기 생성했음). 플레이어가 초상화 확인
  화면에 머무는 시간을 그대로 활용.
- `POST /portrait/retry`: 이전 초상화로 만든 장면 이미지·작업은 무효이므로
  `_reset_scene_jobs`로 먼저 지우고 새로 시작.
- `POST /start`: 더 이상 아무것도 동기로 기다리지 않는다. 이미 준비됐으면 즉시 그
  이미지로, 아직이면 `image_url=null`로 즉시 반환(장면 2~4와 같은 폴링 패턴).
- 실제 API로 검증: 이전엔 `/start`가 항상 20~30초 걸렸는데, 이제 준비된 경우 20ms,
  안 된 경우도 25ms.
- CLAUDE.md 9.3의 "장면1은 대화 화면 진입 전 완료 대기" 문구와 달라지는 지점이라
  사용자 승인 하에 진행.

### 테스트 인프라 이슈 발견·수정
`build_image_generator`(백그라운드 작업이 코드별 API 키를 쓸 때 직접 호출하는 함수)는
FastAPI `dependency_overrides`가 닿지 않는 경로라서, 장면1도 백그라운드로 옮기자 목
환경에서 실제 OpenAI 클라이언트를 만들려다 실패하는 문제가 생겼다. `conftest.py`에서
`app.api.deps`/`app.api.sessions`/`app.api.turns`에 이미 바인딩된 `build_image_generator`
이름을 전부 monkeypatch해서 해결.

테스트 4개 신규 추가(eager 생성 확인, 재시도 시 리셋 확인 등), 전체 110개 통과.

## 실사용 중 발견한 버그 2건 (사용자가 물어본 건 아니지만 검증 중 발견)

**A. 회차 삭제가 배경 이미지 생성과 경합해 500 에러.** 장면 이미지가 20~30초씩 걸려
순차 생성되는데, 그 도중 삭제하면 배경 작업이 새 이미지 행을 커밋해 FK 위반이 났다.
처음엔 Python 레벨 재시도로 고쳤다고 봤으나 실측 생성 시간이 재시도 창보다 길어
여전히 실패 재현됨. **근본 해결**: session_id를 참조하는 모든 FK에
`ON DELETE CASCADE`(비용 로그는 `SET NULL`)를 거는 마이그레이션(`194bd16e37e3`)으로
교체해 `DELETE FROM sessions` 한 문장을 DB가 원자적으로 처리하게 함.
`session_admin.py`가 훨씬 단순해짐. 배경 작업도 세션이 이미 지워졌으면 조용히
멈추도록 방어 코드 추가. 실제 API로 "생성 직후 바로 삭제" 재현 → 200 확인, DB 완전
정리 확인, 배경 로그에 에러도 안 남는 것까지 확인.

**B. 회차 삭제 후 새 회차 생성 시 index 충돌.** `next_index = count(기존)+1`로 계산했는데
삭제가 가능해지며 count가 최대 번호를 보장 못 하게 됨(남은 게 {2,3,4}면 count=3,
count+1=4가 이미 존재). `MAX(index)+1`로 교체. 실제 서버에서 재현 후 수정 확인.

## Codex에게 전달 (2·3·4·6번)
아래 메시지를 그대로 전달함:

1. 장면1 대기 제거에 맞춰, 대화 화면 진입 직후(첫 턴 제출 전) `session.scene.image_url`이
   null인 경우도 기존 이미지 폴링(`turns` 배열 기준으로 도는 `refreshImages`)이
   커버하는지 확인 필요 — `turns`가 비어있으면 폴링 조건이 안 걸릴 수 있음 지적.
2. 이미지 로딩 중 "가게로 가는 중..." 순차 문구
3. 내 메시지 optimistic 표시 (전송 즉시 화면에 먼저 그리기)
4. 타이핑 인디케이터 스크롤 버그 수정
5. 완료 회차 재열람 시 스크롤 힌트 추가
